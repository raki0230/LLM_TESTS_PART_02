# LLM-as-a-Judge

A simple implementation of **LLM-as-a-Judge**, a testing strategy where one LLM evaluates the output generated by another LLM.

The example evaluates a banking-related response across multiple dimensions instead of relying on exact string matching.

## What It Demonstrates

The judge LLM evaluates the generated response based on:

* **Correctness** – Is the information accurate?
* **Relevance** – Does it answer the question?
* **Clarity** – Is it easy to understand?
* **Completeness** – Does it cover the important information?
* **Overall Quality** – Overall assessment of the response.

The evaluation uses a reference answer and returns structured scores from **1 to 10**.


## Tech Stack

* Python
* LangChain
* OpenAI
* Pydantic
* LangSmith
* uv

## Setup

Create the environment and install dependencies:

```bash
uv venv
uv sync
```

Add your OpenAI credentials to `.env`:

```env
OPENAI_API_KEY=your_api_key
```

If LangSmith tracing is enabled:

```env
LANGCHAIN_TRACING_V2=true
LANGCHAIN_API_KEY=your_langsmith_api_key
LANGCHAIN_PROJECT=llm-as-a-judge
```

## Run

```bash
uv run evaluation_test.py
```

Example output:

```text
LLM-AS-A-JUDGE
==================================================

Evaluation:
Correctness   : 9/10
Relevance     : 9/10
Clarity       : 8/10
Completeness  : 8/10
Overall       : 8/10
```

## Key Idea

Instead of testing an LLM response using:

```text
Expected Response == Actual Response
```

LLM-as-a-Judge evaluates the **quality and meaning** of the generated response.

This makes it useful for testing applications such as **RAG systems, chatbots, AI assistants, question answering, and other open-ended LLM applications**.
